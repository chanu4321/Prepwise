## 3. Retrieval (labelled queries)

**Not measured: skipped by the author.** With only 11 papers, a retrieval benchmark says little. A random ordering would already put 91% of the relevant papers in the top 10 (top 5: 45%; first result relevant: 9%; MRR 0.27 for a query with one relevant paper). recall@5 and MRR could still show whether search beats chance, but over about 20 queries on 11 documents even a good score would not support a general claim, so no retrieval number is reported. The corpus is indexed with one vector per paper (section 1).

## Limitations

- **Small corpus.** 11 papers, 5 subjects, 37 pages, and a syllabus for only 1 subject. Retrieval and generation numbers describe this corpus, not a large deployment.
- **The OCR sample is small.** 10 of the corpus's 37 pages (a seeded random sample), transcribed once by the author; one is mostly a diagram. Error rates swing with page condition (flat vs slanted photo), so the per-page table says more than any single average.
- **Rebuilt index.** The production Qdrant cluster had been deleted, so the index was rebuilt locally from the same 11 PDFs with the app's own OCR, embedding and storage code. Paper metadata came from the production database (read-only) rather than being re-extracted.
- **Retrieval was not benchmarked.** At 11 papers the result would be dominated by chance (section 3), so this evaluation makes no claim about search quality.
- **JSON parsing is measured on the batch route only.** The web UI uses the streaming route, which asks for plain text.
- **Bloom adherence is mostly LLM-judged.** The judge can be wrong, and the judge-human agreement on the 30-question sample is the check on it. Questions with no verdict (NVIDIA's gateway cut off calls longer than about 5 minutes) lean towards long, multi-part questions, so the judged set slightly under-represents them.
- **One generation per paper.** The generator samples at temperature 0.6, so a re-run gives different questions. Latency has n=8 per path, from one client in India against a shared, free hosted API at particular times of day; it moves with NVIDIA's load. The routes were called in-process, so the deployed site's nginx/Cloudflare hop is not included.
- **The app's validation is lenient.** Warnings still count as valid, so the strict "no warnings" rate is reported beside it. Some warnings are validator quirks rather than question defects (see 4a).
- **Repetition is not scored.** Questions within a section often revisit the same topic or scenario; no metric here captures that.
- **Dollar costs are assumed, not billed.** The API was used on NVIDIA's free tier. The dollar figure prices the measured tokens at a third-party list price for the same model, and providers' prices for it vary (about 2x across the listings found). The Claude/GPT comparison ignores that those models would use different token counts.
- **The generator changed mid-evaluation.** Before this run, the app's default generator was `z-ai/glm-5.3-flash`. In the superseded run `20261107T180337Z_step4_generation`, 122 of 185 generator calls that reached NVIDIA succeeded (66%), and on 2026-11-10 it stopped answering altogether (a one-word prompt timed out at 150 s while other models answered in seconds). The default was switched to `nvidia/nemotron-3-ultra-550b-a55b` (PR #7) and step 4 was re-run from scratch; no glm number appears in the tables.
- **Interrupted attempts were redone, not hidden.** Attempts cut short by this machine losing its network or being powered off were not scored and were re-run; their API calls stay in the run logs, where each one is documented. Failures on NVIDIA's side (504s, dropped connections, timeouts) were kept and are counted in the reliability figure.

## Reproducing

Every API call (endpoint, model, status, latency, token usage; never keys) is logged in each run's `calls.jsonl` under `eval/runs/` (private; available on request). Scripts, in order: `step0_build_index.py`, `step1_corpus.py`, `step2_prepare_ocr.py` / `step2_score_ocr.py`, `step3_retrieval.py`, `run_step45.ps1` (runs `step4_generate.py`, `step4_judge.py`, `step4_manual_sample.py`, `step45_metrics.py`), then `make_results.py`. Labelling rules were fixed before any labels existed: `eval/data/LABELLING.md`.
